## 가독성 우선 설계

- **보기 좋은 표보다 잘 보이는 표**를 우선한다. 편집 화면은 가급적 단순하게 유지하고, 자주 쓰지 않는 기능이나 불필요한 안내·조작 요소는 줄인다.
- **일일 근무표는 A4 세로 1페이지 고정**으로 설계한다. 출력 가능한 면적을 최대한 활용해 여백을 줄이고 글자와 셀을 크게 표시한다. 단순히 A4 한 장에 들어가도록 축소하는 것이 목표가 아니다.
- 일일 근무표의 **A~C열은 근무 코드 수에 따라 행이 증감**하고, **D열 이후는 항목 수에 따라 열이 증감**할 수 있다. 행·열 수가 바뀌어도 출력 영역을 충분히 채우도록 높이·너비의 균등 배분을 중시한다.
- 글자 크기와 현장 가독성을 우선하며, 양식의 기본 디자인은 거의 고정하고 날짜별 데이터 입력을 간편하게 한다.
- 월간 근무표의 세부 인쇄 배치는 인원 배정에 따라 달라지므로 별도 검토한다.

## 개발 협업 및 검증 방식

- **실제 화면 확인과 기능 테스트는 사용자가 직접 한다.** GitHub 커밋 후 매번 '실제 배포 화면은 확인하지 못했다', '배포 여부를 검증하지 못했다' 같은 상투적인 문구를 반복하지 않는다.
- 어시스턴트는 요청받은 코드 변경을 수행하고 **수정 내용과 커밋 결과만 간결하게 보고**한다. 테스트 결과를 확인한 것처럼 주장하지 않으며, 사용자가 테스트에서 발견한 문제를 알려주면 그에 맞춰 수정한다.
- Cloudflare Workers Builds 자동 배포 구성은 유지한다. 배포 상태 확인이 별도로 필요한 경우에만 요청 또는 작업 맥락에 따라 확인·보고한다.

## 설계·재작성 원칙 (2026-11-23)

### 결과의 동일성은 사용자 스케일에서 판단
- 목표는 최종 사용자가 보는 화면, 가독성, 조작 방식, 기능을 요구 수준에서 재현하는 것이다.
- 내부 코드, DOM, 행·열 구조, 라이브러리, 구현 순서의 동일성은 요구사항이 아니다.
- 사용자가 "결과를 바꿔 달라"고 했을 때 이를 "기존 코드를 부분 수정하라"로 해석하지 않는다.
- 기존 코드는 참고자료이며, 검증된 설계나 보존해야 할 자산이라고 가정하지 않는다. 비슷한 결과를 더 단순하게 재현할 수 있으면 전부 폐기하고 다시 작성해도 된다.

### 취미 프로젝트의 비용 기준
- 이 프로젝트는 실험과 재작성이 허용되는 취미 작업이다. 망가진 시제품은 다시 만들면 된다.
- 코드 보존 비용보다 반복 탐색, 사용자 테스트 시간, 인지 부담, 잘못된 구조를 유지하는 비용을 우선 고려한다.
- 단, 재작성 허용은 저장된 근무 데이터·비밀값·운영 환경을 무단 삭제하거나 초기화해도 된다는 뜻이 아니다.

### 가장 중요한 축적 자산: 시행착오 로그와 FB
- 코드의 최종 상태뿐 아니라 **요구 → 시도 → 관찰 → 실패/성공 조건 → 폐기 이유 → 미검증 대안**을 남긴다.
- 실패 기록을 지우지 않는다. 같은 실패를 반복하지 않도록 연결 가능한 인덱스로 보존한다.
- FB는 결과물 자체의 복사본이 아니라 재연산의 시작점과 연결 경로를 단축하는 참조점이다.
- 반복되는 실패가 공통 구조적 제약을 드러내면 별도 FB로 연결한다. 확인되지 않은 원인을 사실로 단정하지 않는다.

### 작업 순서
1. 사용자 관점의 최종 결과와 허용 오차를 정의한다.
2. 기존 구현의 제약이 결과를 방해하는지 확인한다.
3. **유지 / 부분 수정 / 구조 교체 / 전면 재작성**을 동등한 선택지로 검토한다.
4. 가장 간단한 경로로 구현한다.
5. 결과를 요구사항과 대조한다. 실제 화면 검증은 사용자가 한다.
6. 시도, 관찰, 남은 문제, 폐기한 가정을 로그에 남긴다.

### 사례 인덱스: A4 일일 근무표 셀 편집
- 목표: 노안 사용자가 보기 쉽게 A4 출력 영역을 최대한 활용하고 셀을 크게 조절한다.
- 시도: 기존 공유 행·열 표 구조에서 병합과 선택 행 높이 균등화를 확장했다.
- 사용자 관찰: 병합 후에도 행이 남았고, ABC와 DEF 경계가 어긋났으며, 한쪽 크기 조정이 다른 쪽에 영향을 주었다.
- 잠정 판단: 공유 행 구조가 독립 분할 요구와 충돌할 가능성이 있다. 원인 확정은 아니다.
- 다음 탐색: 기존 구조를 억지로 보존하지 말고 독립 분할 가능한 레이아웃을 포함해 재설계한다. 새 구조의 적합성은 미검증.
