## 1. 목적과 운영 원칙

- **작은 조직에서 실제 사용하는** 월간 근무표 / 휴무 신청 / 일일 근무표 출력용 도구. 모바일 직원 화면, 별도 관리자 화면.
- 취미 개발 프로젝트. 대기업 HR 시스템처럼 승인 프로세스와 예외처리 기능을 무한히 추가하지 않는다.
- **관리자 역할은 기본 규칙 설정과 마감 후 예외 수정**: 날짜별 휴무 신청 가능 인원(월 단위 한도), 해당 월 신청 마감일, 마감 후 휴무 변경, 월간 근무표 편집·배포. 일상적인 휴무 신청·취소는 직원 자율 처리.
- 직원 신청자 **이름을 공개하는 목적은 서로 같은 날 쉬도록 날짜를 맞춰보기 위해서**. 신청 마감/정원 마감과 신청자 조회는 반드시 독립시킨다. 마감 후에도 명단을 읽을 수 있어야 함.
- 갈등·예외 조정은 관리자가 사람을 불러 직접 이야기하면 충분한 경우가 많다. 모든 상황을 온라인 자동화하지 않는다.
- UI 원칙: 큰 글씨, 직관적인 버튼, 쓸데없는 주석·설명·확인단계 최소화. 흑백 프린터를 사용하므로 **일일 출력 양식에 배경색 넣지 말 것**.
- 직원 출퇴근 시간은 **근무 코드 관리**에서만 수정. 이름은 로그인/직원 ID와 연결되므로 일일표에서 직접 이름 자체를 수정하는 기능은 허용하지 않는다.
- 스케줄 공유는 PDF만 남기기로 합의: 캘린더 추가/ICS/구독 기능은 제외(퇴직 직원도 있음).

- 둘 다 **같은 D1**: \`DB\` 바인딩 → \`schedule-test-db\`. DB ID는 각 \`wrangler.jsonc\`에 기록되어 있음.
- 양쪽 Wrangler에 \`keep_vars: true\` 설정. GitHub 공개 저장소이므로 **비밀번호, API 토큰, 접속키, 개인 식별정보를 새로 커밋하지 않는다**. 실제 Secret은 Cloudflare에 남겨둔다.
- DB 초기화 금지. 기존 직원 계정/휴무·근무 데이터는 유지하면서 스키마를 추가·마이그레이션하는 패턴.
- **중요:** Cloudflare 빌드 성공은 코드 배포 성공이지, 기능별 실사용 테스트 성공과 다름. GitHub check run 결과와 필요시 웹 UI/실제 D1 테스트를 구분해 보고한다.
- 문서/테스트 커밋으로도 감시 경로가 맞으면 배포가 일어남. 운영 코드를 건드릴 필요 없는 테스트 변경에 주의.

## 3. 관리자 Worker — 현재 구현되어 있는 주요 기능

### 월간 근무표

- 직원·날짜별 코드 입력, 가로·세로 스크롤, 날짜별 (오전+롱 / 오후+롱) 인원 집계, 근무시간·월 합계.
- 근무 코드별 출퇴근 시간과 구분(**오전/롱/오후**, 야간 코드도 데이터 모델에 존재) 및 색상 편집.
- 월간 근무표 **배포**: 관리자 편집 상태와 직원에게 공개된 월간 근무표를 구분하는 구조. \`schedule_published_shifts\` 및 \`schedule_publications\` 사용. 따라서 직원 월간 근무코드가 보이는 기준과 관리자 편집 데이터는 다름.
- 월간 스케줄 **XLSX 내보내기**.
- 월별 **휴무 마감일**과 **신청 제한 인원** 입력 항목(나란히). 저장하면 **배포 버튼과 무관하게 즉시 D1에 적용**.
- 인원 제한은 월별 하나의 값이 각 날짜의 하루 정원으로 적용됨. 값 미설정은 무제한; 0은 신규 신청 차단. 기존 신청 인원이 새 정원보다 많아져도 자동 취소하지 않음.
- 날짜 선택 후 관리자 휴무 추가/취소/복구 가능(전일, 오전, 오후, 연차). 마감 이후 예외 변경도 관리자 몫.
- 관리자 화면 코드 편집·직원 관리·비밀번호 변경·관리자 세션 기능.

### 직원 계정 관리

- 관리자에서 직원 추가·수정, 직원별 접속키 발급/초기화.
- 직원은 ID + 발급된 접속키로 로그인. **WebAuthn 패스키는 아직 구현하지 않음.**
- 이름 자동완성은 일일표의 근무코드 적용용. **성+이름 일부(예: ‘홍길’)로 후보 조회**, 정확한 직원 계정 ID를 선택해서 코드 변경. 이름 문자열을 임의 수정해 직원 ID를 깨뜨리지 않는다.
- 예전에 **접속키 발급 팝업의 ‘복사’ 버튼은 불필요하므로 다음에 제거**하자는 의견이 있었음. 현재 코드에서 제거되었는지는 확인 후 판단.

### 일일 근무표 편집기 — 가장 최근까지 수정한 부분

- 좌측 메뉴는 **월간(▦) → 일일(日 키캡) → 코드(A 키캡) → 직원관리** 순.
- 화면 제목은 정확히 **‘일일 근무표’**. 날짜 앞/뒤 이동, 월간으로 돌아가기, 출력하기, 되돌리기/다시 실행, 저장하기.
- ‘보기 모드’를 따로 두지 않고 **기본 화면 = 일일 내용/근무코드 입력**, ‘셀 편집’ = 양식 구조·서식 편집. 표는 화면의 **남은 아래 공간을 최대한 차지**하도록 flex 레이아웃.
- 입력 전용 상단 ‘셀 A1 내용’ 프레임은 삭제/숨김. 빈 셀을 선택해 재클릭·더블클릭하거나 키보드로 바로 내용 입력. 공통 양식 텍스트와 선택 날짜 개별 기입을 구분.
- 제목·날짜 등 첫 행 A1의 오래된 기본 문구를 제거. **A1 자체는 제거하지 않았고 빈 병합 셀로 유지**.
- 셀 선택/다중 선택, 드래그 범위, Ctrl/Shift 계열 선택, 셀 병합·해제, 행·열 추가/삭제, 크기 변경, 글씨 크기/굵기.
- 크기 조정은 기본 클릭과 충돌하지 않도록 **셀 편집 모드에서 먼저 셀 선택 후** 해당 셀의 경계 조정이 가능하도록 구현.
- 텍스트나 역할(코드·이름 등)이 든 행·열은 무조건 삭제하지 못하게 보호. 추가는 선택된 행·열 뒤에 삽입.
- 선택 셀의 **테두리** 버튼: 없음/전체/바깥/안쪽/위/아래/좌/우, 0·1·2·3px. 셀 속성으로 저장, 인쇄에도 반영. **흑백 출력**을 염두에 둠.
- **높이 균등** 버튼은 **v20.14.8에서 의미 변경**: 이제 **선택한 행들의 높이값만 평균화**함. 선택한 행들의 총 높이는 보존, 다른 행/기존 병합 범위는 변경하지 않음. 이전 v20.14.7의 ‘열 병합 범위를 재배치’ 방식으로 되돌리지 말 것. 현재 한 병합 셀을 선택하면 그 셀이 걸친 행들이 대상이 됨. 표시되는 ‘행 높이 37’은 병합 셀 전체 높이가 아니라 **개별 행 높이**를 가리킴.
- 일일표는 코드/시간/이름, 오른쪽 휴무·연차·공유 영역, 상단 제목·날짜·하단 기입란을 담는 **하나의 시트**. 행·열 병합, 텍스트, 실제 코드 연결, 흑백 인쇄가 가능한 편집기.
- 저장하기 전에는 **로컬 변경**만 존재. \`Ctrl/⌘+S\` 저장, \`Ctrl/⌘+Z\` 되돌리기, 다시 실행 단축키/버튼, 날짜 이동 시 미저장 경고. **일일 내용·공통 양식·근무 코드**를 \`/api/daily-commit\`에서 묶어 D1 저장. 일일표에서 변경한 코드가 월간 근무표에도 반영됨. 시간 수정은 코드편집에서만.
- ‘출력하기’는 일일표 시트 자체를 인쇄. 행/열 번호, 선택·드래그 조작 UI 없이 인쇄용 시트 생성. 테두리/병합 설정 유지 지향. 출력용 배경색 넣지 말 것.

## 4. 직원 Worker — 현재 구현된 주요 기능

- 모바일 우선 개인 월간 달력, 코드별 근무시간 표시, 휴무 신청/취소 화면.
- 개인 월간 달력을 **현재 보이는 월간 달력 모양 그대로 PDF로 저장**(달력 + 코드). 별도 캘린더 등록/ICS/구독은 제거.
- 월별 신청 마감: **지난달 이전은 신청 불가**. 이번 달/미래 월은 마감일 미설정이면 가능, 해당 월 설정된 마감일을 넘겼으면 불가. 마감 이후에는 직원의 신청·취소 모두 차단, 관리자만 예외 변경.
- 날짜별 신청 제한: 전일/오전/오후/연차 등 유효한 휴무 직원 수를 **직원당 하루 한 자리**로 세고, 정원 초과 시 신규 신청 거절. 서버에서도 정원 검사.
- **신청자 목록은 기한과 독립**: 이미 기록된 유효한 휴무(\`schedule_leaves\`)를 읽어 이름·휴무 종류를 표시. 직원이 직접 신청한 이력(\`employee_leave_requests\`)과 일치해야만 보이는 구식 조건은 제거했음. 관리자 등록분도 표시 대상. 명단의 목적은 직원들끼리 휴무 날짜를 맞추는 것. 취소 기록은 제외.
- 직원 자신의 휴무 취소 가능 여부는 본인 신청 기록과 대조하여 판단. 관리자가 임의 등록한 휴무를 직원 마음대로 취소하게 하지 않는다.
- 직원 근무표 코드는 관리자가 **배포한** 월간 스냅샷에서 읽는 구조. 휴무/신청자 현황은 현재 유효한 D1 휴무 기록을 직접 조회.
- 코드를 확인할 함수: \`leaveAccepting\`, \`getMonth\`, \`leaveAction\`, \`showApplicants\`, \`downloadSchedule\`.

## 5. D1 테이블·저장 경계 (변경 전 실제 스키마 확인)

- 직원 계정: \`employees\`, 직원 접속키·로그인 세션 관련 테이블.
- 관리자 스케줄: \`schedule_codes\`, \`schedule_shifts\`, \`schedule_leaves\`, \`schedule_monthly_hours\`.
- 신청 규칙: \`schedule_deadlines\` (월별 deadline), **\`schedule_leave_limits\`** (월별 max_applicants). 과거 컬럼 방식에서 별도 테이블로 바꾼 것은 월간 스케줄·코드 로딩 장애를 방지하기 위해서. **기존 테이블에 무턱대고 다시 \`max_applicants\` 컬럼을 요구하지 말 것.**
- 직원 직접 신청 이력: \`employee_leave_requests\`.
- 월간 배포본: \`schedule_publications\`, \`schedule_published_shifts\`.
- 일일 양식: \`daily_template_settings\` (공통), \`daily_day_contents\` (날짜별 입력). 일일 저장 시 \`/api/daily-commit\` 사용.
- **관리자 화면의 ‘근무표 배포’와 Cloudflare Worker ‘코드 배포’는 완전히 다른 의미**. 전자는 직원에게 월간 근무표 공개, 후자는 사이트 실행 코드를 배포하는 것.
- 2026년 11월 **테스트용 직원/근무표 샘플 시드**가 관리자 코드에 남아 있음. \`ensureNovemberSampleSeed\`, \`NOV_SAMPLE_ROWS\`, \`dev_sample_202611_seeded_v1\` 플래그. 기동 시 매번 새 데이터를 넣는 일반 운영 데이터가 아님. **테스트용 D1이고 실제 운영 전 샘플 시드 처리 여부를 반드시 다시 검토**.
- Cloudflare D1을 다른 DB로 바꾸거나 초기화하면 두 Worker가 모두 영향받음.

## 6. 개발 중에 확인했던 오류/해결 이유

1. 다음 달도 ‘신청 기간 외’가 되었음 → 기존에는 월별 deadline 미설정을 신청 불가로 해석했음. **지난 월 차단 + 현재/미래 월별 deadline 판단**으로 수정.
2. 마감된 달의 신청자 이름이 안 나옴 → 신청 이력과 휴무 원장을 동시에 요구하는 조건 때문에 관리자 등록·복구 휴무가 누락될 수 있었음. **활성 휴무 원장 기준 조회**로 변경.
3. 인원 제한이 누락됐음 → 관리자의 월간 마감일 옆 제한 인원 추가, 직원 UI 및 서버 정원 검사 추가.
4. 신규 \`max_applicants\` 컬럼이 없을 때 스케줄·코드 로딩까지 깨질 위험 → **\`schedule_leave_limits\` 별도 테이블** 도입.
5. 일일 편집기 클릭 시 크기 조정이 먼저 걸림 → 내용 입력/셀 편집 모드 분리, **먼저 선택 후 리사이즈**.
6. 일일표 아래 여백이 지나치게 큼 → 시트 편집 프레임을 화면 남은 높이까지 확장.
7. 일일표의 ‘셀 A1 내용’ 상단 입력 프레임은 불필요 → 제거, 셀 안에서 직접 편집.
8. A1 기본 제목 글자만 지운 것을 처음에는 ‘프레임 삭제’로 잘못 이해 → A1 빈 셀은 유지하고 입력 프레임은 제거.
9. 테두리 없는 제목/날짜와 굵은 구분선 요구 → 셀별 테두리 0–3px 및 방향 지정 추가, 인쇄 CSS 강제 테두리 제거.
10. 높이가 달라 보이는데 행 높이가 37로 동일하게 표시 → **병합된 여러 행의 전체 높이 vs 한 행의 높이** 구분. 최종 합의는 **선택한 행 높이값 균등화**, 병합 구조 변경 금지.
11. 일부 브랜치 대화가 너무 길어짐 → 이 인수인계 문서와 GitHub 실제 코드를 기준으로 **새로운 대화**에서 이어갈 것.

## 7. 미완성·차기 작업 (구현됐다고 말하지 말 것)

1. **일일 양식에서 월 전체 분량의 일일 근무표를 일괄 생성/내보내기**: 해당 월의 일수만큼 파일·시트를 생성하는 동작. **특정 날짜 하나만 별도 출력/내보내기**는 현재 화면 인쇄가 있지만, 최종 목적의 출력 파일 포맷·일괄 내보내기 동작은 미완성. 추후 폼/행열 크기 조절과 연결하여 구현.
2. **패스키(WebAuthn)**: 희망 기능이나 **아직 미구현**. 지금은 직원별 발급 접속키 로그인.
3. 일일표의 **실사용 UX 점검**: 셀 선택, 병합, 행 높이 균등, 테두리 인쇄, 터치/키보드, 미저장 경고, 새로고침 후 유지 상태를 실제 Cloudflare UI에서 확인하며 수정할 것. 로컬 테스트/CI 성공만으로 모든 기기 동작을 보장하지 않는다.
4. 접속키 발급 팝업의 **불필요한 복사 버튼** 제거 여부 확인.
5. 자동 근무 배정은 후순위 구상(법정시간·출퇴근 간격·우선 인력 배정). 현재 구현으로 간주하지 않는다.
6. 실운영 전 **테스트 데이터 시드·권한·보안 및 별도 백업** 점검. 현재 \`schedule-test-db\`는 시험용.

## 8. 앞으로 ChatGPT가 개발할 때 지킬 절차

1. **현재 GitHub의 \`admin/worker.js\` / \`employee/worker.js\`를 먼저 가져와 읽는다.** 이 문서는 업무 맥락용이고 코드의 현재 사실을 대체하지 않는다.
2. 요청한 기능이 관리자용인지 직원용인지 구분. 해당 Worker만 수정하고 관련 D1 API 스키마 충돌이 있는 경우만 양쪽 변경.
3. 다른 화면/기능을 덮어쓰지 않도록 **최소 범위 수정**. 특히 \`daily_template_settings\`, \`schedule_published_shifts\`, \`schedule_leaves\`, 로그인 ID, 직원 이름 연결을 보호.
4. 코드를 점검하고 가능한 로컬 동작 시험(브라우저, SQL, 저장/되돌리기/인쇄)을 실시.
5. **GitHub \`main\`에 직접 커밋하면 실제 Cloudflare 자동 배포가 시작**됨. 사용자가 수정·배포를 요청했을 때만 코드 커밋. 문서만 수정할 때는 감시 경로를 고려.
6. Cloudflare의 GitHub 체크 상태(진행 중/성공/실패)를 확인하고, **확인하지 않은 배포·운영 동작은 성공이라고 단정하지 않는다**.
7. 새 기능·결정·미완성이 바뀌면 이 \`HANDOFF.md\`를 갱신. **다음 새 대화에서도 이 문서 하나를 시작점으로 사용**.
8. 복사 붙여넣기용 대형 Worker 전체 코드를 매번 대화에 출력하지 말고, **GitHub 링크 + 커밋 + 검증 결과**를 남긴다.
